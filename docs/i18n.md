# Arabic and English

The whole interface works in Arabic and in English. The switch (EN / عربي) is in the top bar and on the
sign-in page. The choice is saved in the browser; on a first visit the browser's language decides.

## How it works

**Frontend** (`frontend/src/i18n.js`)
- Code is written in English. Every visible string goes through `t()`:
  - `t('Sign out')`
  - `t('{n} articles in {week}', { n, week })` (placeholders are `{name}`; never build sentences by concatenation)
  - `tn(n, '{n} article', '{n} articles')` for counts. The Arabic entry for the `other` form (`'{n} articles'`) may be an object of plural forms: `{ zero, one, two, few, many, other }`.
  - `N_('...')` marks a string in a module-level table; translate it with `t(TABLE[key])` when rendering. `t()` must never run at module level: it would freeze the language at import time.
  - `pick(obj, 'name')` reads `name_ar` in Arabic and `name_en` (or `name`) in English. Use it for themes, regions, outlets and any API object that carries both.
  - `fmtDate(d)`, `fmtNum(n)` and `utcFormat('%b %Y')` (d3 axes) give Libyan month names in Arabic with Western digits.
- The Arabic catalogue is `frontend/src/locales/ar/<group>.js`, keyed by the exact English text. One file per group of screens (below).
- Switching language remounts the screens, so every `t()` and every API text is fetched again.
- `<html dir="rtl" lang="ar">` mirrors the layout. Use logical CSS (`margin-inline-start`, `padding-inline-end`, `text-align: start`, `inset-inline-end`) instead of left/right, in CSS and in inline styles. Charts keep left-to-right geometry (time runs left to right); `svg { direction: ltr }` is set globally. Put `dir="auto"` on user text and article titles.
- `scripts/check-i18n.mjs` runs in `npm run build` and fails on visible English that is not wrapped, on a wrapped string with no Arabic, on placeholder mismatches and on module-level `t()`. A line holding English that is never shown (a CSS font string, a log message) carries a trailing `// i18n-ok`.

**Backend** (`backend/app/i18n.py`)
- The browser sends `X-Lang: ar|en` with every request. Middleware puts it in a context variable.
- Wrap user-facing text in `tr()`: error messages (`HTTPException(400, tr("..."))`), notes, labels, reasons. Placeholders as in the frontend: `tr("{n} weeks", n=4)`. (Not `_()`: many endpoints take a parameter named `_`.)
- Module constants keep the English and are wrapped when sent: `tr(FX_NOTE)`. Mark them with `N_()` where defined so the catalogue test sees them.
- Config text that users read has an Arabic twin with the suffix `_ar` (`label` / `label_ar`); read it with `pick()`.
- Long content has an Arabic file next to the English one: `content/how_the_numbers_work.ar.md` (`content_path()` chooses).
- Catalogue: `backend/app/locales/ar/*.json`. `tests/test_i18n.py` fails when a wrapped literal has no Arabic, when an `HTTPException` message is not wrapped, when a source label or config reason has no Arabic, or when a content file has no Arabic version.
- The weekly digest is written once in English and once in Arabic in the same model call (split at `===ARABIC===`); `/api/digests/{id}` returns the brief in the request's language. Briefs from before 2026-10-17 exist in English only, and the page says so.
- Third-party labels shown "as published" (the 2023-24 social-media scrape: authentic/inauthentic, Pro-LNA...) stay in their original English on purpose.
- What the API returns as a code (a reason key, a lens key) is translated in the frontend; what it returns as prose is translated in the backend. Never translate API prose a second time in the frontend.

## Arabic style

- Modern Standard Arabic in a plain news register that Libyan readers use. No Gulf or Egyptian dialect.
- **Address no one by gender.** Arabic imperatives and "you" forms are masculine or feminine, and many users are women. Buttons and menu items use the verbal noun (إضافة مقال، تسجيل الخروج، إرسال), instructions use impersonal forms (يمكن إضافة…، يُرجى…), not أضف / أضيفي.
- Short sentences. Arabic punctuation: ، ؛ ؟
- Western digits (0-9), as Libyan media use. Dates through `fmtDate()`: 17 أكتوبر 2026.
- Keep outlet names, brand names and code (SVG, PNG, CSV, URLs) as they are. The app name stays "Desert Watch".
- Same English term, same Arabic term, everywhere (glossary below). A change to the glossary is made here first.
